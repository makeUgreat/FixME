# Project Conventions
- Follow the [Documentation convention](docs/en/documentation-convention.md) when creating, changing, or reviewing README files, AGENTS instructions, project guides, and cross-project conventions.
- Follow the [API architecture convention](apps/api/docs/en/architecture-convention.md) when creating or reviewing layer boundaries, domain model construction, dependency direction, and mappers.
- Follow the [API naming convention](apps/api/docs/en/naming-convention.md) when creating, renaming, or reviewing API files, classes, ports, DI tokens, DTOs, and controllers.
- Follow the [API error convention](apps/api/docs/en/error-convention.md) when creating, changing, or reviewing API error handling and exception mapping.
- Follow the [API test convention](apps/api/docs/en/test-convention.md) when writing or reviewing tests for the API app.
